## 核心失效根因与三大不可逾越红线

### 🔴 禁令一：严禁任何脚本手拼硬编码 SSML 字符串（导致变调与正音遗漏）
- **血的教训**：在局部测试或调优时，若随手手写一段 SSML 字符串，极易把原本在 JSON 中校正好的“不”字变调（如“不垢不净 bú gòu bú jìng”）误写为四声，导致系统反复翻车！
- **铁律要求**：**严禁任何形式的手写 SSML**。所有测试、样音、母带生成，**100% 必须调用 `SutraSSMLCompiler` 动态读取 `src/data/<book_id>/<chapter_id>.json`**。经文 JSON 是全系统唯一法定真理源。

### 🔴 禁令二：严禁绕过自动化变调与正音门禁（Gatekeeper）
- **铁律要求**：编译前必须强制调用 `assert_phonetics_gatekeeper(data)`，自动扫描经文全量字符：
  1. **“般若”**：必须为 `bō rě`（SAPI: `bo 1 re 3`），严禁读平声“搬”；
  2. **“诸法空相”**：必须为 `xiāng`（SAPI: `xiang 1`），严禁读四声“象”；
  3. **“受想行识”**：必须为 `xíng shí`（SAPI: `xing 2 shi 2`），严禁句末跌入四声；
  4. **“阿耨多罗”**：必须为 `nuò`（SAPI: `nuo 4`），严禁读边音或英语 No；
  5. **“不”字变调**：遇去声（四声）字必须为 `bú`（如“色不异空”、“不灭”、“不垢不净”），其余遇一/二/三声必须为 `bù`。
  **若有 1 处不符，流水线立即硬性抛出异常阻断生成，严禁落盘发布！**

### 🔴 禁令三：严禁在小句内部插断或逐字打桩（导致音律破碎或尾音空悬）
- **血的教训**：在名相内部（如“行深”与“般若”之间）强加断句，会导致前字尾音被拉长下坠，并在字后制造长达几百毫秒的真空断崖；而逐字打桩则会像小学生指读点读机一样生硬破碎。
- **铁律要求**：以标点划分短句，**整个小句整体封装进单个 `<phoneme>`**，字字紧扣、声断气不断，保留汉语自然的轻重音与音渡流转。

### 🔴 禁令四：严禁向 TTS 引擎裸露输入现代情绪与排版标点（导致尖叫、怪调与报菜名）
- **血的教训**：古籍经文非现代话剧！若将感叹号 `！`、问号 `？`、冒号 `：` 直接丢给 TTS 引擎，TTS 韵律预测器会判定为惊叹或质问语气，F0 基频被暴拉导致声音尖锐刺耳（尖尖的）；若对顿号 `、` 插入 380ms 逗号级留白，并列词组会被撕裂成报菜名点读机。
- **铁律要求**：**声学标点强制归一化（Acoustic Punctuation Normalization）**：
  1. **感叹号 `！`**：句中呼赞（世尊！须菩提！）归一为声学逗号 `，`（留白 380ms），句末终结（降伏其心！）归一为平落句号 `。`（留白 250ms），声调沉稳庄严，彻底消除尖叫！
  2. **问号 `？`**：设问结句归一为平落句号 `。`（留白 250ms），彻底消除反问上挑！
  3. **冒号 `：` / 分号 `；`**：引述承转归一为从容逗号 `，`（留白 380ms）！
  4. **顿号 `、`**：微歇留白严格压缩为 **`120ms`**，保持并列韵律紧凑自然！
  5. **装饰标点（引号 `“”`、书名号等）**：在 SSML 中彻底剥除，绝不生成空 phoneme！

### 🔴 禁令五：严禁在经文 JSON 中回写无拼音标点时间戳（导致二分查找断片）
- **血的教训**：若将时间戳写入无拼音的引号（如 `“`），其历史残留脏数据会导致后续段落的 `startTime` 严重倒退（如第 2 品倒退 12 秒），前端 `useAudioSync` 二分查找全部失焦（表现为中间一大片无高亮）！
- **铁律要求**：
  1. 回写前彻底清除非发音字符的 `startTime/endTime`；
  2. 行与段落时间戳 **100% 仅从有效发音汉字提取**；
  3. 增加**单调递增绝对熔断门禁**，段落或行若发生时间戳倒退，立即阻断流水线。

### 🔴 禁令六：严禁对偶排比圣号自注意力弱读与轻声滑脱（Given Information De-accenting）
- **血的教训**：在紧邻对偶排比句（如“如来善护念诸菩萨，善付嘱诸菩萨”）中，现代神经网络 TTS 会判定后一句的“诸菩萨”为已知旧信息，自动将其发音时长压缩、音量下压，且受普通话双音节轻声词先验影响将“萨”读成轻声（`·sa`），听感极度轻浮、轻佻、草率！
- **铁律要求**：
  1. 遇到排比对偶佛门圣号，**自动分离谓语与圣号宾语**；
  2. 针对圣号赋予专属稳健中气加权 **`<prosody volume="+15%" rate="-14%">`**，确保下盘扎实、字字千钧；
  3. **硬去声同音定调**：对圣号“菩萨”注入硬去声同音定调（“菩飒”），彻底破坏现代口语轻声词记忆，迫使女声与男声一样读满沉稳刚劲的第四声（`sà`）；
  4. `clauses_meta` 与底层物理事件必须严格同步切分，确保时间轴毫秒级 100% 精准对齐。

## 标准生产命令 (Universal Master Pipeline CLI)

全藏经文（包含《心经》、《金刚经》等）统一调用固化脚本：

```bash
# 1. 默认女声（晓秋）全篇母带并回写时间轴至 JSON
python scripts/generate_sutra_master.py --book xinjing --chapter chapter_1

# 2. 官方男声（云扬 · 专业演播风格）全篇母带并回写时间轴
python scripts/generate_sutra_master.py --book xinjing --chapter chapter_1 --voice yunyang --output public/audio/xinjing_male.mp3

# 3. 仅生成男声音频不覆盖默认时间轴
python scripts/generate_sutra_master.py --book xinjing --chapter chapter_1 --voice yunyang --output public/audio/xinjing_male.mp3 --no-update-json
```

## 母带交付质检黄金清单 (9-Point Checklist)

每次生成发布前，流水线必须逐一勾选验收：
- [ ] **单一真理源**：是否直接由 `src/data/<book>/<chapter>.json` 动态编译，零手写 SSML？
- [ ] **多音字门禁**：是否通过 `assert_phonetics_gatekeeper`，般若(bō rě)、空相(xiāng)、阿耨(nuò)无误？
- [ ] **变调严谨性**：“色不异空”、“不灭”、“不垢不净”是否 100% 变读二声 bú？
- [ ] **语速对标**：语速是否锁定为参考样例实测标定的 `-11%`？
- [ ] **留白合度**：逗号是否补偿 380ms（实测 ~580ms），句号是否补偿 250ms（实测 ~1000ms），顿号微歇 120ms？
- [ ] **字字相扣**：小句与名相内部是否零 break，彻底杜绝“深”字后空悬？
- [ ] **音色人设**：男声是否开启 `narration-professional`（0.8）专业播音腔体共鸣？
- [ ] **排比圣号**：对偶排比圣号（如“诸菩萨”）是否具备稳健中气加权，杜绝句末轻读轻佻？
- [ ] **高保真直出**：是否为 24kHz 160kbps MP3 原生直出，无额外人工压限与混响？
